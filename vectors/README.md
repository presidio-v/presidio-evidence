# Golden test vectors

**Append-only (ADR-0001 D5).** A published vector is never edited; superseded vectors move to `retired/` with a reason. Every file here is produced by `scripts/generate_vectors.py`; CI fails if the committed files drift from regeneration (`--check`) or if orphan files appear.

| Directory | Pins |
|---|---|
| `signing/` | Cross-repo wire format: detached Ed25519/HMAC-SHA256 over `canonical({content_hash, signer})`, plus tamper cases that must fail closed. `*-golden-v3.json` pin the `@3` message and signatures, including a declared tier and a signer containing `"` and `,`. The Ed25519 vector (priv `01`×32) is byte-identical to the ones committed in the consumer repositories (x402, ikigov-assess and presidio-hardened-ai). |
| `canonical-json/` | Layer-0 strict canonical JSON profile (sorted keys, compact separators, UTF-8, no ASCII escaping, floats rejected) + SHA-256 content hashes. |
| `evidence-ref/` | `presidio-hardened/evidence-ref@1` envelopes: valid (incl. one end-to-end verifiable with companion `.notes.json`), and invalid documents schema validation must reject. |
| `evidence-ref-v2/` | `presidio-hardened/evidence-ref@2` (ADR-0003): assurance tiers. Valid envelopes with an explicit `assurance_tier` per enum value (`attested`/`optimistic`/`zk`) and one with the field absent (documents the `attested` default); invalid cases (unknown tier, missing-now-required `schema`, wrong schema id). Plus `valid-v1-with-extra-tier` — an `@1` record carrying `assurance_tier`, validated against the **@1** schema and expected to PASS (the extra-field finding: `@1` has no `additionalProperties:false`, so the tier is tolerated and ignored). Every `@2` ref reuses the `@1` golden `content_hash`/`signature` verbatim — the signed message is unchanged by the tier. |
| `evidence-ref-v3/` | `presidio-hardened/evidence-ref@3` (ADR-0004): subject binding. The signature covers `{assurance_tier, content_hash, framework, item_id, signer}`. `valid-*` and `tampered-*` files are schema-valid envelopes, `invalid-*` are schema-invalid; `expectations.json` gives, per ref, whether the signature verifies, whether it verifies for `expected_framework "iki-gov"`, and the CLI verdict, and both lanes assert that table. Covers relabelled item, framework and tier, an `@2` signature presented as `@3` and the reverse, `@3` refs in a schema-absent envelope, one artefact honestly backing two items, and a ref signed for a foreign framework. `evidence-ref-v2/reused-ref.json` pins the `@1`/`@2` reuse floor. Framework ids: `iki-gov` (IKI-Gov checklist `S1`–`I5`); a producer registers its vocabulary here when it adopts `@3`. |
| `cloud-posture/` | scoutsuite consumer vector: clean AWS controls for IKI-Gov items O5 and T5 as `evidence-ref@2` refs, built the way presidio-hardened-scoutsuite 0.30.0 builds them (claim subject → content hash → family signing message). The notes pin the 0.29.x legacy signatures (every ref field signed) as must-fail. Cross-checked at creation against scoutsuite's own functions. |
| `trust-store/` | `presidio-hardened/trust-store@1`: valid store (Ed25519, rotation lists, HMAC back-compat forms) and invalid stores. Two schema-valid stores the verifier must still read safely (audit 2026-10-25): `rejected-hmac-with-public-key` (load fails: a public key is never an HMAC secret) and `public-key-implies-ed25519` (an entry with `public_key` and no `alg` is Ed25519; an HMAC forged with the public key as secret must not verify). |
| `training-run/` | ADR-0002 provenance-parents: a parents-bearing `presidio-hardened/training-run@1` Layer-0 payload (shape per arch-translucency `build_training_run_reading`) wrapped in a signed `evidence-ref@1` envelope. `lineage` (`parents`) lives inside the signed content; companion `.notes.json` carries the Layer-0 reading, signed content, and trust store. `valid-envelope-energy` adds the v0.23 OPTIONAL `energy_wh` / `mean_power_w` fields (producer claims, E1a) to that same payload and nothing else — **additive & conditional** (ADR-0011): strip them and it re-hashes byte-identically to `valid-envelope`, so the pre-v0.23 vector is untouched. Decimal strings, coherent with `duration_s` (840 Wh over 2 h == 420 W); byte-for-byte pat's L-EV-7 self-pin `d674a115…`. |
| `workshop-attestation/` | Schema freeze for `presidio-hardened/workshop-attestation@1` (ikigov-assess T-B4): a presidio-as-assessor countersignature whose `attests`/`parents[0]` reference the `training-run/` payload's content hash — the ADR-0002 DAG edge (L-EV-6). ASCII-only, float-free. |
| `workshop-leavebehind/` | ikigov-assess consumer vector: an OWNER-signed `presidio-hardened/workshop-leavebehind@1` manifest (T-B4 R1, additive `owner` block inside the signed content). Pins two profiles: the manifest's canonical sha256 (the `attests` target of a workshop attestation — the DAG edge) and the owner Ed25519 signature over the **raw canonical manifest bytes** (manifest.sig profile, deliberately not the `{content_hash, signer}` message). Cross-checked against ikigov's own verifier at creation. |
| `slo-reading/` | x402 consumer vector: a `presidio-hardened/slo-reading@1` Layer-0 degradation reading (`value > threshold`) signed into an `evidence-ref@1` envelope — the pat → signing-bridge → x402 SLO payment broker chain. `item_id`/`ledger_ref` byte-identical to arch-translucency `build_slo_evidence` output (cross-checked at creation). |
| `energy-reading/` | **Reserved** for the arch-translucency Energy Arc v0.24 "Sign the watt" (its L-EN-4) — no shipped producer emits this yet; the vector is the contract pat must match. A key-less `presidio-hardened/energy-reading@1` Layer-0 reading in a signed `evidence-ref@1` envelope. Two vectors: nominal (`parents` omitted per ADR-0002 P3) and parents-bearing, whose `parents[0]` is the `training-run/` payload's content hash — the energy-axis DAG edge ("these are the joules that run cost"). Joules and watts are shortest-round-trip decimal **strings**, never floats (D1), and `mean_power_w` is re-derivable from `energy_wh` and the window. `energy_chain_head` (the head of pat's chained `energy_observations` store, its ADR-0011 §2) sits inside the signed content, so a signed reading attests the unrewritten history behind it; the family pins only its hex discipline. |
| `treasury-checkpoint/` | Treasury consumer vector, **Layer 0 only** (ADR-0001 D1): `treasury-close/checkpoint/v1` identity = sha256 over the canonical envelope, including null-valued optionals and i64 nanosecond timestamps. No signature by design (keyless dual-control trust model). |
| `numeric-encoding/` | ADR-0005 (Proposed) numeric payload encoding: decimal strings in plain notation with a per-field precision. `validate` cases for the verifier (byte-wise grammar, never a float parse: `"0.00001"` ok; `"1e-05"`, `"12.0"`, `"-0"`, `"NaN"` rejected), hand-written `encode` cases for the producer (half-even rounding), and inputs the producer must refuse. canonical-json@1 is unchanged. |
| `gate-certificate/` | ADR-0006 (Proposed): a `presidio-hardened/gate-certificate@1` as ikigov-assess emits it, issuer-signed with the family test key. Its identity is sha256 over canonical-json@1 of the document minus `signature` (the bytes the issuer signs), pinned in the notes. `child-training-run` is a `training-run@1` reading whose `parents[0]` is that identity: the run → gate edge. Cross-checked at creation against ikigov-assess v0.28.0. |

Two well-known private keys live in this repo as cross-repo fixtures, not secrets: the family test key `01`×32 (producer/assessor signers) and the customer test key `02`×32 (workshop owner signatures).
