# Architecture

This document describes the high-level design of `presidio-evidence`: its
components, how data flows through them, and the trust boundaries the project is
built to enforce. For the security requirements and threat model that motivate
this design, see [SECURITY.md](SECURITY.md) and the assurance case in
[ASSURANCE.md](ASSURANCE.md). Design decisions are recorded in
[docs/adr/](docs/adr/).

## Overview

`presidio-evidence` is the signed-evidence substrate of the presidio-hardened-*
family: a contract (JSON Schemas under `schemas/` and golden vectors under
`vectors/`), a stateless Python library that implements it, a small CLI, and a
Rust crate that proves the same wire format in a second language. A producer uses
it to content-address a payload and sign a reference to it; a consumer uses it to
check that reference against a trust store before acting on it. The library is
stateless, makes no network calls, stores no keys and logs nothing. Its design
stance is **fail closed**: bad evidence verifies as `False` with a reason, and a
malformed envelope raises `EvidenceError`; neither can be read as a pass.

## Components

Listed from the primitives outward; each layer only imports the ones above it.

| Component | Responsibility |
|---|---|
| `_errors.py` | `EvidenceError`, the single exception type for malformed input. |
| `_constants.py` | Frozen contract constants: schema ids, the eight `evidence-ref@1` fields, assurance tiers, signing algorithms, the `framework` pattern. |
| `_canonical.py` (Layer 0) | Strict canonical JSON (sorted keys, compact separators, UTF-8, floats and NaN rejected) and SHA-256 content addressing. Stdlib only. |
| `_numeric.py` (Layer 0) | ADR-0005 decimal strings: one spelling per value, so two producers that agree on a number agree on the hash. The verifier side never converts to float. |
| `_gate_certificate.py` (Layer 0) | ADR-0006 identity of a `gate-certificate@1` document: the hash of its canonical bytes without the `signature` field. |
| `_signing.py` (Layer 1) | The signed messages (`@1`/`@2`: signer-bound; `@3`: subject- and tier-bound) and detached Ed25519 / HMAC-SHA256 signatures. Ed25519 comes from `cryptography` (`[crypto]` extra); HMAC from the stdlib. |
| `_refs.py` (Layer 1) | Envelope parsing (`parse_document`, `load_evidence`), trust-store loading (`load_trust_store`), `verify_ref`, the `@1`/`@2` reuse floor (`reused_refs`) and the full per-envelope policy (`verify_envelope`). |
| `_keys.py` | Ed25519 key generation and fail-closed loading from a `0600` file or an environment variable. No key storage. |
| `_contract.py` | Locates the shipped `schemas/` and `vectors/` trees (package data in a wheel, the repository root in a checkout). |
| `_cli.py` | `presidio-evidence verify` (exit 0 only if every ref verifies) and `keygen`. |
| `rust/` | Rust crate (`publish = false`): Layer 0 and the signing messages, with its own conformance suite over the same vectors. |
| `schemas/`, `vectors/` | The normative contract. Vectors are generated by `scripts/generate_vectors.py` and append-only (ADR-0001 D5). |

Layer 2 (approval semantics, e.g. treasury's dual control) is out of scope by
design (ADR-0001 D1).

## Data / processing flow

**Producer:** payload → `canonical_bytes` → `content_hash` → signed message for
the chosen schema (`signing_message` for `@1`/`@2`, `signing_message_v3` for
`@3`) → `sign_evidence` / `sign_evidence_v3` → ref → `build_envelope`.

**Consumer** (`verify_envelope`, also behind `presidio-evidence verify`):

1. `parse_document` validates the envelope: a known schema id, the eight required
   fields as bounded strings (≤ 512 chars, no NUL, valid UTF-8), lowercase-hex
   hash and signature, no control characters in `item_id`/`signer`, `framework`
   required and well-formed under `@3`. Any violation raises `EvidenceError`;
   nothing is verified from a malformed envelope.
2. Per ref, in this order, the first failing check decides the reason:
   a declared `optimistic`/`zk` tier is not verifiable here (ADR-0003 D6); with
   `expected_framework`, only an `@3` ref for that framework may pass (ADR-0004
   D4); an `@1`/`@2` ref claimed for several items fails (D5); then the signature
   is checked against every key listed for the signer (rotation).
3. The envelope's schema selects the signed message; the presence of a field
   never does, so a signature made for one major never verifies as another.

The failure posture is fail closed throughout: `verify_ref` returns `False` for an
unknown signer, a bad key, a non-hex signature or a malformed mapping, and the CLI
exits non-zero unless every ref verifies. The library does not check that
`content_hash` matches the evidence itself, nor that `item_id` belongs to the
consumer's vocabulary; both stay with the consumer, which holds the content.

## Trust boundaries

| Boundary | Kind | Control |
|---|---|---|
| **Producer → envelope → consumer** (evidence in transit) | Input validation | `parse_document` structural checks; signature verification against the consumer's trust store; subject binding under `@3`; reuse floor under `@1`/`@2`. |
| **Operator → trust store** | Input validation (trusted configuration) | `load_trust_store` normalises entries; `public_key` is Ed25519 only and is rejected under `hmac-sha256`, so a published key never acts as an HMAC secret. The store's content is trusted: whoever controls it decides which signers are believed. |
| **Operator → private key** | Input validation, secret handling | `load_private_key` accepts a regular file with mode `0600`/`0400` (checked with `fstat` on the opened descriptor) or an environment variable, reads at most 256 bytes and never puts key material in an error. `write_private_key` refuses to overwrite. Custody stays with the operator. |
| **Library → CLI output** (egress to a terminal or log) | Egress | Identifiers are printed JSON-escaped, one line per ref, and control characters are rejected at parse time, so a producer cannot forge verdict lines or terminal escapes. |
| **Contract → consumers** (schemas and vectors as published) | Integrity of the wire format | Golden vectors pin exact bytes; `scripts/generate_vectors.py --check` and both conformance suites fail CI on any drift; changes are append-only and pass a required code-owner review. |
